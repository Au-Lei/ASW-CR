# 港口与新版表格改造任务

## 目标与字段约定

目标表头：提单号、起运港、目的港、ETD（原BC）、Valid to、ETD、当前状态、备注。

- 起运港取官网 Basic Information 中的 Port of Loading。
- 目的港取同一 Basic Information 表中的 Port of Discharge；不得取 Place of Delivery。
- 最新 ETD 仍取 Port of Loading 行的 Estimated Departure Date。
- 同一次查询提取三个字段，不增加逐票网站访问次数。
- 港口以官网名称为依据，可去掉末尾国家代码括号，如 SHANGHAI (CN) → SHANGHAI；保留原始抓取文本用于诊断，不能粗暴删除港名中的所有括号。
- 备注默认由人工在金山表格维护，程序读取和展示，不生成、不覆盖；网页编辑备注不属于本次默认范围。
- 原始 ETD、Valid to 均由人工维护，同步不修改。

## 任务 1：现状检查与方案（已完成）

现有抓取返回 etd、raw、pol，尚无 pod；pol 只在本地查询结果展示。
AirScript 把原始 ETD、Valid to、最新 ETD 固定为 B/C/D 列，直接使用新表会被拒绝。
当前状态已经按表头定位，但高亮范围仍固定为 A:D。
本地订单以 JSON 存储，可以增量添加港口和备注字段，无须清空数据库。

## 任务 2：表头映射与金山脚本（本地实现与模拟验证已完成）

- 建立字段到列号映射，规范空白、全半角括号和已有别名。
- 支持现有旧格式与截图新格式；新格式港口列成对出现。
- 缺失、重复或歧义表头时拒绝写入，提示具体列名。
- 读取 pol、pod、remark；写回仅允许最新 ETD、港口和当前状态。
- 写入前重新定位单号和表头，校验本次要更新字段的原值，避免覆盖查询期间的人工修改。
- ETD 变动时按业务列范围高亮，新格式覆盖 A:H；仅补全港口不触发黄色高亮，不清除原有高亮。
- 验收：旧表、新表、调换列位置、重复表头、行移动、备注不被覆盖均通过模拟测试。

## 任务 3：官网解析（本地实现与离线验证已完成）

- 在同一查询结果表中唯一定位装货港和卸货港，沿用 ETD 表头定位规则。
- 缺失、空白或多义港口不写空值覆盖表格；保留已有港口并明确报告未识别字段。
- 如出现重复候选、ETD 歧义或无法确认结果归属，不执行该票自动写回。
- 验收：以截图结构制作离线 HTML，覆盖 colspan、国家代码、重复行、缺失目的港，以及不同于卸货港的收货地/交货地。

## 任务 4：同步与历史兼容（本地实现与离线验证已完成）

- 扩展 WPS 客户端契约及服务层字段传递，读取后采用金山表格最新港口与备注。
- ETD 不变时也允许补全或修正可确认的港口；仅更新发生变化的字段。
- 分开记录日期变更、港口变更和写回确认结果，港口更新不能冒充 ETD 更新计数。
- 保留现有四种业务状态及“北京时间今天晚于最新 ETD 才已完成”规则。
- 历史页仍只收录实际 ETD 成功变更且变更后晚于 Valid to 的记录；港口或备注变化不产生此类历史。
- 验收：全量、单票、勾选同步一致；未选中行不被更新；旧本地历史无需转换即可展示。

## 任务 5：网页展示（本地实现与离线验证已完成）

- 主表按新业务顺序展示单号、起运港、目的港、原始 ETD、Valid to、最新 ETD、当前状态、备注。
- 同步前 ETD、同步结果和查询时间作为辅助信息保留，避免混淆金山现值与本次官网查询值。
- 搜索扩展至单号、港口、备注；长备注换行或展开查看，保持单票和勾选入口可用。
- 历史可展示变更时的港口与备注快照，后续修改备注不应改写旧历史。
- 验收：空值、长港名、长备注、窄窗口，以及外部文本安全渲染。
