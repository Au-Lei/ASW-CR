# WPS配置、业务规则与排错

## 表格布局

使用普通共享电子表格，不是多维表格。第一行为表头：

推荐使用新版布局：

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| 提单号 | 起运港 | 目的港 | ETD（原BC） | Valid to | ETD | 当前状态 | 备注 |

脚本按第一行表头定位，不依赖列号；旧格式“提单号、ETD（原BC）、Valid to、ETD、当前状态”继续兼容，各列可以调换顺序。单号支持“提单号/订舱号/单号”，原始日期支持“ETD（原BC）/ETD（原始）”，最新日期支持“ETD/最新ETD”。每种业务字段只能出现一次，别名同时出现也视为重复。起运港与目的港必须成对出现；备注可选。

单号按文本保存，不丢前导零。原始 ETD、Valid to 和备注由人工维护，脚本不修改；原始日期和期限不能为空时的业务校验仍由程序执行。

表头支持部分空格及全半角括号兼容。日期使用完整 `YYYY-MM-DD` 或真实表格日期。旧月日文本需要明确DATE_YEAR；小数10.21不会被猜成10月21日。

## AirScript安装

在目标表格新建JavaScript AirScript，把 `wps/etd_bridge.js` 全部复制进去并保存。在编辑器生成脚本Token并取得webhook地址。Python调用同步接口 `/sync_task`；若复制的是异步 `/task`，改为同路径的 `/sync_task`。

在项目根目录的.env设置WPS_WEBHOOK_URL、WPS_API_TOKEN及底部标签WPS_SHEET_NAME。文档分享链接不能代替webhook，文档顶部标题不能代替底部工作表标签。

[官方同步执行API](https://airsheet.wps.cn/docs/en-US/apitoken/api.html)、[脚本Token指引](https://airsheet.wps.cn/docs/en-US/apitoken/intro.html)。

## 比较与更新

| 情况 | 行为 |
|---|---|
| 官网日期不同于原始日期、也不同于最新 ETD 列 | 写入最新 ETD 列 |
| 官网日期等于原始日期，最新 ETD 为空 | 不写 |
| 官网日期与最新 ETD 列一致 | 不重复写 |
| 官网恢复原始日期，最新 ETD 仍有延期旧值 | 最新 ETD 更新为恢复后的日期 |
| 查询失败、日期无效或重复单号 | 该票失败，旧日期保留 |
| 写入超时/校验失败 | 写入待确认，重新读取WPS |

写回脚本按单号重新定位，核对原始 ETD 和最新 ETD 原值，然后按表头写入最新 ETD 并读回确认。查到有效ETD不等于成功写入，网页仅把后者计为已更新。

ETD 写入并校验成功后，金山共享表格（WPS）对应行从最左到最右已识别业务列的范围（新版为 A:H，旧版包含当前状态列）设置为浅黄色背景（`#fff3b0`）；只读取、日期未变化或写入校验失败时不新增标黄。已有背景会保留，不在后续同步时自动清除。背景设置失败也会提示写入待确认，应先读取核对实际日期。

网页订单列表与历史变更中的“已更新”行显示浅黄色背景；后续查询结果为“无需变更”时网页按当前状态显示，WPS 中的黄色仍保留。

启用 WPS 标黄需将本地 `wps/etd_bridge.js` **完整替换到原 WPS AirScript 并保存**。本地代码更新或重启网页不会自动更新 WPS 脚本。更新已有脚本时保留原 webhook 和 Token。

## 逐步联调

```powershell
.\.venv\Scripts\python.exe -m etd_sync --read-only
.\.venv\Scripts\python.exe -m etd_sync --limit 1
.\.venv\Scripts\python.exe -m etd_sync --apply --limit 1
```

前两步不写WPS；第三步实际写入。网页版“手动同步数据”直接执行读取、查询、写回，没有额外预览确认。

## 常见问题

- 工作表不存在：检查底部标签名是否完整一致。
- 表头不匹配：核对第一行是否缺少或重复业务字段，更新的本地脚本也需要重新粘贴到WPS保存。
- 日期解析失败：改用完整年月日，不要使用数字小数表示月日。
- 无官网结果：核对到底是订舱号还是提单号，检查EVERGREEN_NUMBER_TYPE。
- 单号重复：人工确认是否同票多行，当前程序不会猜测要写哪一行。
- 写入待确认：先读取核对真实WPS值，不要立即反复同步。
- 官网超时或验证码：稍后重试或人工查询，不降低提取校验去强行写回。
- HEADLESS=false无可见浏览器：此配置只作用于CLI；Web服务始终后台查询。

查询器按Port of Loading行与Estimated Departure Date列定位，并处理合并列；不能直接使用预计到港或预计装船列代替ETD。

## 历史变更记录筛选

历史页只展示成功写回且变更后 ETD 严格晚于该次同步读取的 Valid to 的记录，并显示 Valid to 列。不展示同步任务列表；任务日志继续保留在系统运行记录中。此条件仅影响历史页，不限制 ETD 正常写回与标黄。

最新 ETD 等于或早于 Valid to、Valid to 为空或无效的记录不展示。旧历史缺少 Valid to 时不使用当前表格日期补推，也不补录为新变更。符合条件的历史不受最近 30 次任务的展示限制。

新版 AirScript 的 read 操作按表头读取 `valid_to` 并校验存在唯一的 Valid to 表头；请完整替换原脚本并保存，之后新同步才可按此规则记录历史。

## 当前状态（手动同步时更新）

添加唯一的“当前状态”列（旧格式通常为 E1，新格式为 G1）；程序按表头定位，可放在其他列。四个状态按以下优先级判断：

| 优先级 | 条件 | 当前状态 |
|---|---|---|
| 1 | 北京时间今天晚于官网最新 ETD | 已完成 |
| 2 | 最新 ETD 晚于 Valid to | 托班到下一批次 |
| 3 | 最新 ETD 与原始 ETD 不同，且未超过 Valid to | ETD已变更 |
| 4 | 最新 ETD 等于原始 ETD，且未超过 Valid to | ETD未变更 |

ETD 当天不自动算已完成；最新 ETD 等于 Valid to 不算超期。完成按预计日期判断，不代表查询到实际离港信息。状态在每次手动同步、官网查询成功后刷新，不安排每日定时修改；只点击“读取订单”不会改状态。

ETD 未变化时，仍会核对状态，必要时仅写回状态列；此操作不新增 ETD 变更历史，也不新增黄色背景。完成状态不会阻止下次查询；官网改回未来日期时会重新计算状态。

查询失败保留状态。未来船期缺少有效 Valid to 时，不能确定状态，提示异常而不猜测；请先填写完整日期。写回时校验原始 ETD、已有 ETD、Valid to 和原状态，发现外部修改则拒绝覆盖。写回失败或超时提示待确认，需读取 WPS 核对。

升级必须完整替换并保存 WPS AirScript；旧脚本不返回当前状态时，程序提示升级，不会继续进行缺字段的同步。webhook 和 Token 保持原配置。

## 单票与勾选同步

- 输入 WPS 中的完整单号并点击“同步此单”，或点击订单行右侧“单票同步”。
- 勾选多个订单后点击“同步选中订单”。勾选跨搜索和筛选保留；表头全选仅选择当前筛选结果，已隐藏的选择仍保留并计入已选票数。
- 原“手动同步数据”仍同步全表，不受筛选或勾选影响；未选订单会重新读取 WPS，但不会发起官网查询或写回。
- 每次指定同步先重新读取 WPS，以单号确定目标，不能沿用旧行号；目标已删除则整次拒绝执行并提示重选，重复单号跳过。未选中订单保留最近查询结果。
- 单票与勾选同步都实际写回，遵循 ETD 更新、当前状态、浅黄色背景、历史筛选及写前校验规则。无需为本次选择功能再次变更 AirScript；仍需已安装支持 Valid to 和当前状态的新版脚本。

## 表头映射脚本接口（schema_version=2）

当前本地源码已接通脚本兼容、官网同页港口解析及 Python 港口写回；网页的港口、备注独立列与搜索也已完成。升级脚本不会让旧 EXE 自动开始抓取目的港，EXE 需配套重新打包。

`read` 返回 `schema_version: 2`、字段到列号的 `columns`，以及订单数组。存在对应表头时，订单额外包含 `pol`（起运港）、`pod`（目的港）、`remark`（备注）；空单元格为 null。没有港口列的旧表不返回港口字段。

原有 `update` 和 `update_status` 调用保持兼容。调用方也可以在写入时携带 `pol`/`pod`，每个携带的港口必须提供 `expected_pol`/`expected_pod` 原始值（空单元格明确传 null）。只补全港口可使用 `update_ports`，沿用 `order_no`、`expected_original`、`expected_latest`，至少提供一个非空港口及对应原值。

脚本写入前校验表头、单号唯一性、日期/状态/港口参数和待更新字段的原始值。港口原值已被修改时整次拒绝，不能通过省略 expected 值跳过检查。备注不在允许写入的字段内，查询期间人工改备注不会被覆盖。仅港口或状态变化不新增黄色背景。

金山脚本的多单元格写入不具备数据库事务保证；写入中途或设置背景失败时仍须重新读取核对，不能把失败理解为所有单元格都未写入。

## 官网港口解析结果（任务 3）

同一次网页查询返回 `etd`、`raw`（原始日期文本）、`pol`、`pod`、`pol_raw`、`pod_raw` 和 `warnings`。起运港来自 Port of Loading，目的港来自同表的 Port of Discharge，不使用 Place of Receipt / Place of Delivery 或其他表格的港口。

港口去掉末尾两个大写字母的国家代码括号；当尾部国家全称与代码吻合时，也去掉明确匹配的国家后缀（目前支持 CN/MY/TH/IN/DE）。例如 QINGDAO, CHINA (CN) → QINGDAO、PASIR GUDANG, MALAYSIA (MY) → PASIR GUDANG。保留港名内部括号和其他未确认后缀，原始文本仍用于核对。缺失或空白港口返回 null 并附带提示，不以交货地补猜目的港。重复港口行、日期表头歧义、列宽不匹配或无法可靠解析的合并单元格均拒绝解析。原有 ETD 空白或无效时仍整票失败。

本阶段通过基于截图结构的模拟 HTML 离线验证，未访问真实订单或写入金山表格。缺失港口时的原值保留、页面行结果提示及写回确认已由任务 4 接入本地源码。

## 港口同步与历史兼容（任务 4）

全量、单票、勾选同步使用同一套规则：

- 新表有起运港、目的港列时，仅写回官网非空且与表格不同的港口；没有港口列的旧表继续仅同步日期与状态。
- ETD 变化时，港口与 ETD 通过一次 `update` 写回；ETD 不变但港口变化时，通过一次 `update_ports` 写回，必要时同时校正当前状态。
- 官网港口缺失时保留表格原值，其余可确认字段继续同步，行结果和运行日志显示提示。结构歧义或港口内容无效则拒绝该票自动写入。
- 写入返回必须确认目标单号、港口脚本版本及全部请求更新的字段；不确认、发生冲突或超时时提示“写入待确认”。本地不把未确认的官网值冒充已写回值，应重新读取 WPS 核对。
- `queried_pol` / `queried_pod` 表示本次官网查询值；订单的 `pol` / `pod` 表示读取或写回确认的表格值。原始抓取文本、警告、成功更新的港口字段及时间单独保存。
- 同步结果分别记录 `etd_updated_count`、`ports_updated_count`、`warning_count`；一票可同时贡献 ETD 和港口计数。港口更新不计入页面的 ETD“已更新”统计，不触发黄色背景，也不生成 ETD 变更历史。
- 历史仍只收录成功 ETD 变更且变更后严格晚于当次 Valid to 的记录。历史保存当次港口和备注快照，后续读取人工修改的备注不会改写旧历史。旧数据库和缺少港口的历史继续可用，无须清空。

源码网页已提供港口、备注独立列及扩展搜索，同步结果说明和运行日志继续展示港口更新与缺失提示。CLI 的预览模式同样只报告待修改项，`--apply` 才实际写入港口。

## 新网页展示（任务 5）

主表的业务列按金山新表顺序排列：单号、起运港、目的港、ETD（原BC）、Valid to、ETD、当前状态、备注；右侧保留同步结果、查询时间和单票操作。列较多时可在表格内横向滚动，右侧操作列固定。

ETD 主值为最近读取或写回确认的表格值；其下显示官网查询日期和同步前日期。没有写入确认时，不会将官网查询值冒充表格现值。港口同样以表格确认值为主，未写回的不同查询值以“官网查得”单独标注。空值和缺字段的旧记录显示“—”。

搜索支持单号、起运港、目的港和备注全文，不区分英文大小写，仍与状态筛选及勾选逻辑配合。备注支持换行，长备注可用鼠标或键盘展开查看，自动刷新或切换搜索后保持展开状态；程序只显示备注，不提供编辑或覆盖。

历史新增港口和变更时备注列，仅使用该条历史自身保存的字段；旧历史没有港口或备注时显示“—”，不拿当前订单值回填。所有外部文本以纯文本方式渲染，备注中的 HTML 不作为网页执行。
